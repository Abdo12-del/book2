# نظام إنتاج الكتب العربية (DOCX + PDF)

منظومة عمل متكاملة لبناء كتاب عربي من **مصدر واحد** إلى مخرجين:
ملف **Word قابل للتحرير** بأنماط حقيقية، وملف **PDF** مطابق للتصميم المعتمد.

```
        book/*.md  ──┬──▶  tools/build_docx.py  ──▶  output/book.docx
      (مصدر واحد)    │
                     └──▶  tools/build_pdf.py   ──▶  output/book.pdf
                                    │
        design/theme.yaml (نظام التصميم الموحّد)
```

المبدأ: **لا نعدّل ملف Word وملف PDF كلًّا على حدة.** كل تغيير يُجرى على المخطوطة
أو على نظام التصميم، ثم تُعاد عملية البناء في أقل من ثانية.

---

## ١. البنية

| المسار | الوصف |
|---|---|
| `book/book.yaml` | بيانات الكتاب وترتيب الفصول (Spine) — **المرجع الوحيد للترتيب** |
| `book/*.md` | فصول المخطوطة بصيغة ماركداون عربي موسّع |
| `book/images/` | صور الكتاب وأشكاله |
| `design/theme.yaml` | نظام التصميم: القياسات، الخطوط، الألوان، التباعد، الترويسات |
| `assets/fonts/` | الخطوط (ترخيص OFL، قابلة للتضمين) |
| `tools/` | أدوات البناء والفحص |
| `output/` | مخرجات البناء: `book.pdf` و `book.docx` وصور المراجعة |

## ٢. الأوامر

```bash
# تهيئة البيئة مرة واحدة (حزم بايثون + الخطوط)
bash tools/setup_env.sh

# بناء الكتاب كاملاً (DOCX + PDF)
python3 tools/build.py

# بناء مخرج واحد، أو تسمية مخصّصة
python3 tools/build.py --only pdf --name book-v2

# فحص الجودة (بعد كل بناء)
python3 tools/qa_check.py output/book.pdf output/book.docx \
        --source book/ --theme design/theme.yaml --render output/pages

# فحص صلاحية الخطوط قبل البناء
python3 tools/check_fonts.py --source book/

# صورة مُجمّعة للمراجعة البصرية
python3 tools/preview.py output/book.pdf output/preview.png --cols 4
```

## ٤. نظام التصميم (`design/theme.yaml`)

كل القياسات بالمليمتر وأحجام الخطوط بالنقطة. أهم المفاتيح:

- `page`: القياس (A5/B5/A4/مخصص)، الهوامش، هامش التجليد، التمهيد المتقابل.
- `fonts`: خط المتن وخط العناوين والمصاحب اللاتيني.
- `sizes` و `colors`: مقياس المطبعية ولوحة الألوان.
- `layout`: التباعد، منع انفصال العناوين، بداية الفصل على صفحة فردية.
- `running`: الترويسات والتذييلات ونمط ترقيم الصفحات.
- `toc` و `objects`: الفهرس، وتعليقات الجداول والأشكال.

## ٥. ما يتحقق منه نظام ضمان الجودة تلقائياً

**في PDF:** عدد الصفحات وقياسها، تضمين الخطوط، اكتمال النص العربي (مطابقة
المخطوطة بعد التطبيع)، absence المحارف المفقودة من الخط (NUL)، تجاوز الهوامش،
العناوين اليتيمة في أسفل الصفحة، الصفحات الفارغة، انعكاس الهوامش بين الفردي والزوجي.

**في DOCX:** سلامة حزمة OOXML، **ترتيب عناصر XML وفق مخطط Word** (أي خلل هنا
يجعل Word يرفض الملف)، اتجاه RTL على مستوى الأقسام والفقرات، الأنماط المستخدمة،
الفقرات الفارغة المتراكمة، الجداول والصور، وجود حقول TOC و PAGE و STYLEREF.

## ٦. قيود معروفة (تُدار بوعي، لا تُخفى)

1. **لا يوجد LibreOffice أو Word في البيئة**، لذا لا مسار «تحويل DOCX → PDF».
   البديل المُطبَّق: مخرجان من مصدر واحد — وهذا أدقّ تصميمياً من التحويل.
2. **الخطوط في PDF يجب أن تحتوي الأشكال السياقية** (Presentation Forms).
   خطوط مثل Tajawal وAlmarai وNoto Kufi Arabic **تُسقط حروفاً** في هذا المسار.
   استخدم `tools/check_fonts.py` قبل اعتماد أي خط (الحالي: Amiri للمتن،
   Noto Sans Arabic للعناوين، وNoto Naskh Arabic بديل للمتن).
3. **التشكيل (الحركات):** لا يطبّق ReportLab تموضع العلامات (GPOS)، لذا قد
   تنزاح الحركات قليلاً. النص غير المشكّول يظهر سليماً تماماً.
4. **الأرقام في DOCX:** شكل أرقام الصفحات (١٢٣ مقابل 123) يتبع إعدادات
   التعويض الرقمي في Word، أمّا في PDF فمحدَّد بالنظام.
5. **تضمين الخطوط داخل DOCX** غير مُفعّل بعد (يضاف عند الطلب عبر ODTTF)؛
   يحسُن تثبيت الخطوط على الجهاز الذي سيفتح الملف.
